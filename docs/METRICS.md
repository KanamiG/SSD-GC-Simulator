# Metrics and CSV semantics

All measures are generated by the simulator. They do **not** represent measured
NAND I/O latency, real SSD endurance, or manufacturing characteristics.

## Counters

| Name | Definition |
| --- | --- |
| Attempted writes | Length of the workload LPN sequence. |
| Successful writes | Calls to `FTL::writeManaged` returning `true`. |
| Failed writes | Attempted minus successful writes. |
| Host page programs | Successfully completed host writes (`FTLMetrics::host_writes`). |
| GC migration programs | Physical page programs performed to relocate valid victim pages. |
| Total physical programs | All successful page programs, including host and GC writes. |
| GC cycles | Successfully completed migrations and victim erases. |
| Block erases | Sum of all successful block erases; in the current GC path it equals GC cycles. |
| Max erases per block | Maximum `eraseCount()` over all physical blocks. |
| Mapped logical pages | Number of unique live LPN entries in the FTL mapping. |
| Free physical pages | Sum of `Free` page counts over blocks, not the count of mapped LPNs. |

`runBenchmark()` reports **deltas** from its initial FTL metrics for an
individual invocation; CLI creates one fresh FTL per invocation. In the normal
CLI model, `total physical programs = host page programs + GC migration
programs`.

## Derived values

Write amplification factor (WAF) uses successful **host writes** as the
denominator, not requested writes:

```text
WAF = total physical programs / host page programs
```

WAF is undefined if there are no successful host writes. `--writes 0` displays
`WAF: n/a` and writes an **empty** WAF CSV cell.

```text
success rate = successful writes / attempted writes
```

Success rate is undefined for zero attempted writes (display `n/a` and empty
CSV cell).

Erase-count coefficient of variation is the **population** standard deviation
of per-block erase counts, divided by their mean:

```text
mean   = sum(erase_counts) / blocks
sigma  = sqrt(sum((erase_count - mean)^2) / blocks)
erase_cv = sigma / mean      if mean > 0, otherwise 0
```

`erase_cv` is defined as 0 when there have been no erasures, rather than `n/a`.
Smaller erase CV indicates more uniform erase counts in the **current run**;
it does not by itself demonstrate longer real-world device life.

## CLI CSV schema

`ssd_sim --csv FILE` appends exactly one run per row with this 26-column header
(in this order):

```text
blocks,pages_per_block,physical_pages,ftl_logical_capacity,logical_pages,writes_requested,workload,policy,lambda,seed,hot_set_size,hot_probability,attempted,successful,failed,success_rate,waf,host_page_programs,gc_migration_programs,physical_programs,gc_cycles,block_erases,max_erases,erase_cv,mapped_logical_pages,free_physical_pages
```

All count fields are integer values; `success_rate`, `waf`, and `erase_cv` are
numeric where defined. The CLI writes floating-point CSV values at 17 digits
of precision. `hot_set_size` and `hot_probability` still appear for non-HotCold
workloads as the effective CLI defaults, but they are not used in those runs.

The CSV export creates missing parent directories; it rejects mismatched
headers and incomplete final lines, and it is **not safe for concurrent
writers** to the same file.

### Do not mix experiment CSV formats

The optional `experiment_wear_weight` executable produces
`results/wear_weight_sensitivity.csv` (320 rows), which has **a separate
schema**. `scripts/analyze_wear_weight.py` validates that experiment layout and
does *not* accept the CLI CSV file. The maintained analyzer produces four
summary CSVs and 10 PNG plots using its own assumptions. See
[scripts/README.md](../scripts/README.md).

## Fair policy comparisons

Compare policies using the same geometry, logical-page range, workload kind,
number of writes, seed, and (for HotCold) hot-set/probability parameters.
A different workload can dominate the observed WAF/erase differences.
Seed-based comparisons are toolchain-specific because C++ random
distributions are not specified to emit identical samples across libraries.
